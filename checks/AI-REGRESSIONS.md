# AI 서버 회귀 검사

2026-09-14 인수인계 검토에서 확인한 오류를 수정했다. 운영 AI 호출, 운영 DB 변경, 배포는 수행하지 않았다.

## 실행

웹 소스 루트에서 다음을 실행한다.

```sh
node checks/handoff-repro.mjs
npm run typecheck
npm run simulate
npm run edge
```

`handoff-repro.mjs`는 실제 소스를 메모리에서 불러오며 외부 의존성은 모의 객체로 대체한다. 9개 검사 그룹이 영수증 총액, 입력한 사람, 응답 본문 타임아웃, 잘못된 응답, 사용량 DB 오류, 예약 계약, 실패한 호출 유지, 장부 조회 오류·잘린 결과를 다룬다.

격리된 SQL 검사는 PGlite 0.5.8을 작업용 디렉터리에 설치해 실행했다. 웹 앱의 의존성은 추가하지 않았다.

```sh
node checks/ai-reservation-sql.mjs
```

다른 위치에 설치한 경우 PGlite를 찾을 수 있는 `package.json`의 절대 경로를 첫 인수로 전달한다. 이 검사는 실제 마이그레이션을 메모리 DB에 적용해 28개 조건을 검증한다. 함수 실행 권한, 실제 익명 호출 거절, 월·장부 범위, 예약·완료·실패 집계, 잘못된 한도 거절을 확인한다.

PGlite는 연결이 하나이므로 여러 PostgreSQL 트랜잭션의 실제 동시 실행을 검증하지 않는다. 배포 전 격리된 PostgreSQL의 기본 READ COMMITTED 환경에서 병렬 예약 검사가 추가로 필요하다. [PGlite 문서](https://pglite.dev/docs/)

## 변경된 계약

- 기존 AI 액션의 입력과 성공/실패 반환 형태는 유지한다. 품목 OCR 결과에 `totalRead: boolean`을 추가했다. `false`면 `total`은 표시용 품목 합계이고 실제로 읽은 총액이 아니다. 이 경우 `balanced`도 반드시 `false`이며 사용자가 총액을 확인해야 한다.
- 채팅에 `LEDGER_AI_ASK_TIMEOUT_MS`를 추가했다. 기본 12초이며 모든 AI 경로에서 헤더와 응답 본문을 함께 제한한다. 기존 OCR·품목·한 줄 입력의 제한 변수는 유지한다.
- 영수증 분류 제안은 식비·이동·물품·활동·기타를 사용한다.
- 장부 채팅 자료에 실제 송금·입금 확인 상태는 없다. 정산 확정과 송금 계획을 실제 돈이 오간 사실로 답하지 않도록 자료와 프롬프트에 명시했다. 이는 모델 지침이며 응답의 모든 숫자를 코드로 검증한다는 뜻은 아니다.
- `loadLedger`는 하위 조회의 오류와 전체 건수에 못 미치는 반환을 거절한다. 현재 서버의 반환 상한을 넘는 장부는 명시적으로 실패하며, 전체 페이지를 읽는 기능은 아직 추가하지 않았다.

## 마이그레이션과 배포 순서

`supabase/migrations/20260914132427_atomic_ai_usage_reservation.sql`을 서버 코드보다 먼저 적용해야 한다. 이 파일은 Supabase CLI 2.117.0의 `migration new`로 생성했고 운영에는 적용하지 않았다.

`reserve_ai_usage(ledgerId, model, limit)`는 장부별 트랜잭션 잠금 후 월 사용량을 확인하고 기존 `ai_extractions` 테이블에 예약 행을 삽입한다. 모든 성공·실패·예약 행을 같은 UTC 월 기준으로 센다. 응답 후에는 새 행을 삽입하지 않고 해당 예약 행을 갱신한다. 외부 서비스가 비용을 청구했는지 불확실한 실패도 예약을 유지한다.

새 함수와 조회 함수는 `SECURITY INVOKER`, 빈 `search_path`, `service_role` 전용 실행 권한을 사용한다. 일반 클라이언트는 이 RPC를 직접 호출하지 않는다. 마이그레이션이 없거나 사용량을 확인·기록하지 못하면 AI 요청은 실패한다. `aiReservationReady()`는 예약을 소비하지 않고 준비 상태를 확인한다.

기존 서버가 병행 운영되는 동안에는 옛 호출 경로가 예약 없이 AI를 부를 수 있으므로, 마이그레이션 적용만으로 월 한도 동시성 문제가 해결됐다고 판단하면 안 된다. 모든 AI 서버 경로가 예약 방식을 사용하도록 배포를 마친 뒤 확인해야 한다.
