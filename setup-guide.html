키는 파일에만 넣습니다.

아래에서 복사하는 값은 전부 비밀번호와 같습니다. .env.local 파일에만 넣고, 대화창·이슈·스크린샷·깃 저장소에는 절대 올리지 마세요. .env.local은 .gitignore에 이미 들어 있습니다.

특히 SUPABASE_SERVICE_ROLE_KEY는 데이터베이스를 통째로 여는 키입니다. 브라우저로 나가는 코드에 들어가면 안 되므로 NEXT_PUBLIC_을 붙이지 않습니다.

00

준비

10분
  1. 00-1
    Node 20 이상이 깔려 있는지 확인합니다. 
    node -v

    v20 미만이면 nodejs.org에서 LTS를 받습니다.

  2. 00-2
    Windows만 — PowerShell에서 npm을 쓰려면 스크립트 실행을 한 번 허용해야 합니다. 
    Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

    이 단계를 건너뛰면 npm install이 npm.ps1 cannot be loaded because running scripts is disabled로 멈춥니다. CurrentUser 범위라 내 계정에만 적용되고, 인터넷에서 받은 서명 없는 스크립트는 계속 막힙니다. 묻는 말에 Y를 누르고, PowerShell 창을 닫았다 다시 엽니다.

    정책을 바꾸고 싶지 않다면 매번 npm.cmd install처럼 .cmd를 붙여 쓰는 방법도 있습니다.

  3. 00-3
    받은 ledger.zip을 풀고, 그 폴더 안으로 들어갑니다. 
    cd ~\Downloads\ledger

    앞으로의 모든 명령은 이 폴더 안에서 실행합니다. C:\Users\이름 같은 홈 폴더에서 npm install을 치면 설치할 목록이 없어 아무 일도 일어나지 않습니다. dir을 쳐서 package.json이 보이면 맞는 자리입니다.

  4. 00-4
    의존성을 설치합니다. 처음 한 번은 몇 분 걸립니다. 
    npm install
  5. 00-5
    환경변수 파일을 만듭니다. 앞으로 복사하는 값을 전부 여기에 넣습니다. 
    copy .env.example .env.local

    macOS·Linux에서는 cp .env.example .env.local입니다.

  6. 00-6
    그 파일을 여는 법을 익혀 둡니다. 앞으로 값이 나올 때마다 여기로 돌아옵니다. 
    notepad .env.local

    VS Code를 쓰면 code .env.local도 됩니다. 그냥 텍스트 파일입니다.

    적는 방식 — 파일 안에 이미 NEXT_PUBLIC_SUPABASE_URL= 같은 줄이 준비돼 있습니다. 새 줄을 만들지 말고, 그 줄의 = 바로 뒤에 붙여 넣습니다. 

    NEXT_PUBLIC_SUPABASE_URL=https://abcdefghijklm.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...

    = 앞뒤에 띄어쓰기를 넣지 않습니다. 따옴표도 붙이지 않습니다. 키는 200자가 넘어 한 줄이 길게 늘어지는데, 보기 싫다고 줄바꿈을 넣으면 안 됩니다. NEXT_PUBLIC_SUPABASE_URL 줄에 들어 있는 https://xxxxxxxx.supabase.co는 예시일 뿐이니 지우고 덮어씁니다.

    #으로 시작하는 줄은 설명입니다. 그대로 두면 됩니다. 다 적었으면 Ctrl+S로 저장합니다.

    값을 채워 넣은 뒤 개발 서버가 이미 돌고 있었다면 껐다 다시 켜야 반영됩니다. 환경변수는 서버가 시작할 때 한 번만 읽습니다.

  7. 00-7
    계정 두 개를 미리 만들어 둡니다. supabase.com · developers.kakao.com

    둘 다 무료로 시작할 수 있습니다.

01

Supabase 프로젝트

10분
  1. 01-1
    Supabase 대시보드에서 New project를 누릅니다.

    Region은 Northeast Asia (Seoul)을 고릅니다. 팀원이 전부 한국에 있으면 가장 빠릅니다. Database Password는 따로 적어 두세요. 나중에 잃어버리면 재설정해야 합니다.

    생성에 2~3분 걸립니다.

  2. 01-2
    Project URL을 가져옵니다. 가장 빠른 길은 프로젝트 화면 위쪽의 Connect 버튼입니다. Connect → App Frameworks → Next.js

    거기 나오는 NEXT_PUBLIC_SUPABASE_URL 줄을 그대로 쓰면 됩니다. Settings → Data API의 Project URL 칸에도 같은 값이 있습니다.

    형태는 언제나 https://<ref>.supabase.co입니다. <ref>는 프로젝트마다 다른 20자쯤 되는 문자열로, Settings → General의 Project ID와 같은 값이고 브라우저 주소창의 /project/ 뒤에도 그대로 보입니다. 02-2에서 다시 씁니다.

    Project URL → NEXT_PUBLIC_SUPABASE_URL
  3. 01-3
    키 두 개를 가져옵니다. Settings → API Keys

    탭이 API Keys와 Legacy API Keys 둘로 나뉘어 있습니다. 어느 쪽을 써도 동작합니다.

    Publishable key (sb_publishable_…) 또는 legacy anon → NEXT_PUBLIC_SUPABASE_ANON_KEY Secret key (sb_secret_…) 또는 legacy service_role → SUPABASE_SERVICE_ROLE_KEY

    각 값 옆의 복사 아이콘을 누르고, notepad .env.local로 파일을 열어 해당 줄의 = 뒤에 붙여 넣습니다. 적는 방식은 00-6과 같습니다. 비밀 쪽 키는 Reveal을 눌러야 값이 보입니다.

    legacy anon·service_role은 2026년 말 폐지 예정이므로, 새로 시작하는 지금은 API Keys 탭의 새 형식을 쓰는 편이 낫습니다. 환경변수 이름은 그대로 둡니다.

    secret(service_role) 키는 공개되면 데이터베이스가 통째로 열립니다. 절대 밖으로 내보내지 마세요. 이 값에는 NEXT_PUBLIC_이 붙은 줄을 쓰지 않습니다 — 그 접두사가 붙은 값은 브라우저까지 그대로 나갑니다.

    세 줄이 제대로 들어갔는지 보려면 type .env.local (macOS·Linux는 cat .env.local)로 파일을 그대로 찍어 봅니다.

  4. 01-4
    초대 링크 통행증 서명 키를 만듭니다. 터미널에 그대로 붙여 넣으면 값이 나옵니다. 
    node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
    나온 값 → LEDGER_COOKIE_SECRET

    이 키가 바뀌면 이미 발급된 통행증이 전부 무효가 됩니다. 팀원들이 초대 링크로 다시 들어와야 합니다.

03

로그인

15분
  1. 03-1
    구글 로그인부터 켭니다. 비밀번호가 없는 설계라 이쪽이 주된 길입니다. Google Cloud Console → API 및 서비스 → 사용자 인증 정보

    OAuth 클라이언트 ID 만들기 → 웹 애플리케이션을 고릅니다. 처음이라면 OAuth 동의 화면을 먼저 만들라고 합니다. 사용자 유형은 외부, 앱 이름은 Ledger, 지원 이메일은 본인 것으로 채우면 됩니다.

    승인된 리디렉션 URI에 Supabase 주소를 넣습니다. 우리 서비스 주소가 아닙니다.

    https://<ref>.supabase.co/auth/v1/callback
    클라이언트 ID → Supabase의 Client ID 클라이언트 보안 비밀 → Supabase의 Client Secret
  2. 03-2
    Supabase로 돌아가 Authentication → Providers → Google을 켜고 위 두 값을 넣습니다.

    여기까지 하면 로그인이 됩니다. 아래 이메일 링크는 구글 계정을 안 쓰는 팀원을 위한 보조 수단이라, 나중에 해도 됩니다.

  3. 03-3
    Authentication → Providers → Email을 켭니다. 기본으로 켜져 있는 경우가 많습니다.

    비밀번호는 쓰지 않습니다. 메일로 온 링크를 누르면 들어오고, 계정이 없으면 그때 만들어집니다.

    메일이 오지 않는 것이 정상입니다. Supabase가 기본으로 붙여 주는 발송기는 프로젝트 팀원으로 등록된 주소로만 보내고, 그마저 시간당 2통입니다. 팀원들에게 실제로 보내려면 03-5의 개인 SMTP가 필요합니다. 그때까지는 구글 로그인을 쓰세요.

  4. 03-4
    Authentication → URL Configuration에 주소를 등록합니다. Site URL → http://localhost:3000 Redirect URLs → http://localhost:3000/auth/callback

    나중에 배포하면 실제 도메인 주소를 추가합니다. 지우지 말고 둘 다 두면 로컬에서도 계속 됩니다.

  5. 03-5
    무료 플랜은 메일 발송 한도가 낮습니다. 팀플 규모면 충분하지만, 막히면 Authentication → Emails에서 개인 SMTP(예: Gmail)를 연결합니다.
04

카카오 로그인

나중에

이 장은 건너뛰어도 됩니다. 카카오 로그인은 비즈니스 앱 전환을 마쳐야 동작합니다. Supabase가 카카오에 account_email 동의항목을 반드시 요구하는데 (연동 코드에 박혀 있어 앱에서 뺄 수 없습니다), 그 항목은 비즈앱에서만 켤 수 있기 때문입니다. 전환 전에 누르면 KOE205가 뜹니다.

그래서 기본값은 카카오 버튼을 감춘 상태입니다. 아래를 다 마친 뒤 .env.local에 NEXT_PUBLIC_KAKAO_LOGIN=1을 넣으면 로그인 화면에 버튼이 나타납니다. 그전까지는 이메일 가입만으로도 전부 됩니다.

  1. 04-0
    비즈니스 앱으로 전환합니다. 사업자등록번호가 없어도 됩니다. 앱 관리 → 일반 → 비즈니스 정보 → 사업자 정보 등록

    개인 개발자는 카카오디벨로퍼스 계정 본인인증과 카카오비즈니스 통합 서비스 약관 동의만 하면 전환됩니다. 전환하면 account_email을 동의항목으로 켤 수 있게 됩니다.

  2. 04-1
    카카오 개발자센터 → 내 애플리케이션 → 애플리케이션 추가하기로 앱을 만듭니다.

    앱 이름과 사업자명은 나중에 바꿀 수 있습니다.

  3. 04-2
    앱 설정 → 플랫폼 키 → REST API 키에서 키를 복사합니다. 잠시 들고 있습니다.

    JavaScript 키가 아닙니다. 그건 05에서 씁니다.

    예전에는 앱 키라는 메뉴에 세 종류가 모여 있었지만, 지금은 플랫폼 키 아래에서 키 종류별로 나뉘어 있습니다.

  4. 04-3
    카카오 로그인 → 활성화 설정을 ON으로 바꿉니다.

    켜지 않으면 로그인 시도에서 KOE004가 납니다.

  5. 04-4
    Redirect URI를 등록합니다. 카카오 로그인 화면이 아니라 키 쪽에 있습니다. 앱 설정 → 플랫폼 키 → REST API 키 → Redirect URI

    콘솔이 개편되면서 Redirect URI가 [카카오 로그인]에서 [플랫폼 키]로 옮겨졌습니다. 카카오 로그인 화면을 아무리 봐도 없는 이유가 이것입니다. 키 종류마다 따로 있으니 REST API 키 쪽에 넣습니다 — Supabase가 서버에서 REST API 키로 카카오와 통신하기 때문입니다.

    넣을 값은 Supabase 주소입니다. 우리 서비스 주소가 아닙니다.

    https://<ref>.supabase.co/auth/v1/callback

    <ref>는 01-2에서 확인한 그 값입니다. 카카오가 로그인 결과를 Supabase에 먼저 넘기고, Supabase가 우리 /auth/callback으로 넘깁니다. 그래서 여기에는 Supabase 주소가 들어갑니다.

    주소가 한 글자라도 다르면 로그인에서 KOE006이 납니다.

  6. 04-5
    클라이언트 시크릿을 확인합니다. 04-4의 같은 화면에 있습니다. 앱 설정 → 플랫폼 키 → REST API 키 → 클라이언트 시크릿

    예전에는 [카카오 로그인] → [보안]이었지만 Redirect URI와 함께 여기로 옮겨졌습니다. 카카오 로그인 화면에 보안 메뉴가 없는 이유가 이것입니다.

    최근에 만든 앱은 REST API 키가 시크릿이 켜진 상태로 추가됩니다. 그러면 값만 복사하면 됩니다. 값이 가려져 있으면 보기 버튼을 눌러 확인합니다.

    꺼져 있다면 코드를 생성한 뒤 활성화 상태를 "사용함"으로 바꿔야 합니다. 생성만 하고 활성화를 안 하면 로그인이 실패합니다.

  7. 04-6
    카카오 로그인 → 동의항목에서 닉네임을 필수 동의로 켭니다. 프로필 사진은 선택입니다.

    켤 때 동의 목적을 적어야 합니다. 이 문장은 로그인할 때 팀원들이 동의 화면에서 그대로 읽게 되므로, 실제로 하는 일만 적습니다. 아래를 그대로 붙여 넣어도 됩니다.

    닉네임

    장부에 지출을 기입한 사람과 정산 대상자를 이름으로 구분해 표시하기 위해 사용합니다.

    프로필 사진 — 선택으로 켠다면

    팀원 목록과 지출 내역에서 작성자를 알아보기 쉽게 표시하기 위해 사용합니다.

    "서비스 이용을 위해", "회원 관리를 위해" 같은 뭉뚱그린 문장은 반려될 수 있습니다. 어느 화면에서 어떻게 쓰는지가 드러나야 합니다.

    이메일도 켜야 합니다. 04-0에서 비즈앱으로 전환했다면 카카오계정(이메일) 항목이 목록에 나타납니다. 선택 동의로 켜 주세요. Supabase가 이 항목을 반드시 요구하기 때문에, 켜지 않으면 KOE205로 막힙니다.

    선택 동의라 팀원이 이메일 제공을 거절할 수 있습니다. 그래도 04-8을 켜 두면 이메일 없이 계정이 만들어져 로그인은 정상적으로 끝납니다.

    동의 목적 예시

    로그인한 계정을 구분하기 위해 사용하며, 장부에는 표시하지 않습니다.

    KOE205가 뜬다면 괄호 안에 어느 항목인지 적혀 있습니다. account_email이면 위의 이메일 항목이 아직 꺼진 것이고(또는 04-0을 아직 안 한 것), profile_nickname·profile_image면 그 항목이 꺼진 것입니다. 적힌 항목을 이 화면에서 켜면 됩니다.

  8. 04-7
    Supabase로 돌아가 Authentication → Providers → Kakao를 켜고 두 값을 넣습니다. 04-2의 REST API 키 → Client ID 04-5의 Client Secret 코드 → Client Secret
  9. 04-8
    같은 화면에서 Allow users without an email을 켭니다.

    이메일 동의는 선택이라 팀원이 거절할 수 있습니다. 이걸 켜 두지 않으면 거절한 사람의 로그인이 실패합니다. 가장 자주 걸리는 지점입니다.

  10. 04-9
    마지막으로 .env.local에 아래를 넣어 버튼을 켭니다. 
    NEXT_PUBLIC_KAKAO_LOGIN=1

    개발 서버를 껐다 켜면 로그인 화면에 카카오로 계속하기가 나타납니다. 위 단계를 다 마치기 전에는 넣지 마세요. 눌러도 오류만 납니다.

05

카카오톡 공유

5분
  1. 05-1
    같은 앱의 앱 설정 → 플랫폼 키 → JavaScript 키를 복사합니다. JavaScript 키 → NEXT_PUBLIC_KAKAO_JS_KEY
  2. 05-2
    같은 JavaScript 키 화면에서 사이트 도메인을 등록합니다. 앱 설정 → 플랫폼 키 → JavaScript 키 → 사이트 도메인 
    http://localhost:3000

    도메인도 Redirect URI와 마찬가지로 키마다 따로 설정합니다. 04-4에서 REST API 키에 넣은 것과는 별개이니, 여기서 한 번 더 등록해야 합니다.

    배포하면 실제 도메인도 추가합니다. 등록하지 않은 도메인에서는 공유가 동작하지 않습니다.

  3. 05-3
    검수는 필요 없습니다. 공유는 사용자가 직접 보낼 채팅방을 고르는 방식이라 별도 권한이 없습니다.

    참고로 서버가 대신 메시지를 보내는 "친구에게 메시지 보내기" API는 비즈니스 검수가 필요하고 승인 전에는 하루 30건 제한입니다. 그건 쓰지 않습니다.

06

영수증 분석

5분
  1. 06-1
    Anthropic Console → API keys → Create Key로 키를 만듭니다. 만든 직후 한 번만 보이니 바로 복사합니다. 키 → ANTHROPIC_API_KEY
  2. 06-2
    크레딧을 충전합니다. 구독이 아니라 미리 넣어 두고 쓰는 방식입니다. Console → Settings → Billing → Buy credits

    Update payment method 창에 카드 정보를 넣고, 충전할 금액을 정해 확인하면 됩니다. Billing 메뉴가 안 보이면 그 조직에서 Admin 또는 Billing 권한이 있는 계정인지 확인합니다.

    5달러면 충분합니다. 영수증 한 건 분석에 약 15원이라 400건 넘게 쓸 수 있습니다. 한 팀이 한 학기에 기록하는 건수가 보통 100~200건입니다.

    Auto-reload는 꺼 두세요. 잔액이 떨어지면 자동으로 다시 결제되는 기능입니다. 학기 프로젝트에서는 예상 못 한 청구를 막는 편이 낫습니다.

    크레딧은 구입 후 1년이 지나면 소멸하고 환불되지 않습니다. Claude Pro나 ChatGPT Plus 구독과는 별개입니다. 구독이 있어도 API 크레딧은 따로 충전해야 합니다.

    이 키로 나가는 비용은 전부 키 주인이 냅니다. 팀원이 영수증을 올릴 때마다 내 크레딧이 줄어듭니다. 그래서 LEDGER_AI_MONTHLY_LIMIT으로 장부당 월 상한을 걸어 두었습니다(기본 200건). 상한을 넘으면 수동 입력으로 안내합니다.

    기본 모델은 Sonnet입니다. 한국어 상품명을 정확히 옮겨 적는 일에서 작은 모델은 '패리시 팬츠'를 '파리시 펜츠'로 바꿔 놓기 때문입니다. 값이 부담되면 .env.local에 LEDGER_AI_MODEL=claude-haiku-4-5를 넣어 한 건 4원짜리로 낮출 수 있습니다. 대신 이름이 조금씩 틀립니다.

  3. 06-3
    지금 건너뛰어도 됩니다.

    영수증 자동 분석은 편의 기능입니다. 이 장을 비워 두면 지출을 손으로 적게 될 뿐, 장부·정산·검산은 전부 그대로 동작합니다. 07로 먼저 넘어가 서비스를 띄워 보고, 쓸 만하다 싶을 때 돌아와도 늦지 않습니다.

08

나중에

배포할 때
  1. 08-1
    도메인을 등록합니다. 이 서비스의 주소입니다. 
    teamledger.net

    여러 해를 한 번에 등록하고, 자동 갱신과 도메인 잠금을 켭니다. 정산 링크는 카카오톡 대화방에 몇 년이고 남습니다. 갱신을 한 번 놓쳐 주소를 잃으면 그동안 나간 링크가 전부 죽습니다. 이 서비스에서 도메인은 장식이 아니라 링크의 수명입니다.

    .net은 프리미엄 등급이 없어 값이 평평합니다(연 $12.52). 짧은 ledger.day는 등록기관이 프리미엄으로 잡아 매년 $64.93을 받기에 접었습니다. 사전에 있는 단어가 들어간 새 끝자리는 대개 이렇습니다. 결제 화면에 Premium이나 Aftermarket 딱지가 보이면 그건 되팔이 매물이니 사지 않습니다.

  2. 08-2
    Vercel에 배포하고 환경변수를 그대로 다시 등록합니다. 도메인을 붙일 때 apex와 www를 둘 다 등록하고, www는 apex로 넘깁니다. teamledger.net (본 주소) www.teamledger.net → teamledger.net 로 넘김

    .env.local 파일은 배포되지 않습니다. Vercel 대시보드에 따로 넣어야 합니다.

  3. 08-3
    주소 두 곳에 실제 도메인을 추가합니다. 로컬 주소는 지우지 않습니다. Supabase → URL Configuration → Site URL 
    https://teamledger.net
    Supabase → URL Configuration → Redirect URLs 
    https://teamledger.net/auth/callback
https://www.teamledger.net/auth/callback
    카카오 → 앱 설정 → 플랫폼 → Web 사이트 도메인 
    https://teamledger.net
    카카오 Redirect URI는 그대로 둡니다 (Supabase 주소라서 안 바뀝니다)
  4. 08-4
    광고를 붙일 거라면 순서가 있습니다. 코드는 이미 다 되어 있고, 남은 것은 구글 쪽 절차입니다.

    먼저 배포가 끝나 있어야 합니다. 애드센스는 실제로 열리는 사이트에 내용이 있어야 심사를 받아 줍니다.

    1 · adsense.google.com 에서 사이트 등록 → teamledger.net 2 · 심사 통과 후 광고 단위(디스플레이 광고)를 하나 만든다 3 · 게시자 ID와 광고 단위 ID를 환경변수에 넣고 다시 배포한다 
    NEXT_PUBLIC_ADSENSE_CLIENT=ca-pub-0000000000000000
NEXT_PUBLIC_ADSENSE_SLOT=0000000000

    ads.txt 는 따로 만들 것이 없습니다. 위의 게시자 ID를 넣으면 teamledger.net/ads.txt 가 그 값으로 자동으로 만들어집니다. 애드센스가 "ads.txt 문제"라고 알려 오면 대개 환경변수를 넣고 다시 배포하지 않은 것입니다.

    자동 광고(Auto ads)는 반드시 꺼 두세요. 켜면 구글이 화면을 골라 광고를 끼워 넣습니다. 그러면 정산 금액 옆에도 광고가 붙습니다. 이 서비스에서 광고는 품목·아카이브 화면에만 들어갑니다.

    개인정보 처리방침은 /privacy 에 이미 있습니다. 화면 맨 아래 줄에서 열립니다. 애드센스 심사에서 요구하는 문서입니다.

체크 상태는 이 브라우저에만 저장됩니다.

Supabase와 카카오 개발자센터의 화면 이름은 바뀔 수 있습니다. 글자가 조금 달라도 하는 일이 같은 항목을 찾으면 됩니다.
